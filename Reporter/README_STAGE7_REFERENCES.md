# Этап 7 — универсальный просмотр справочников

Добавлен первый универсальный браузер справочников поверх метаданных `app.TflexGroup` и политик `app.GroupAccessPolicy`.

## Главное

- один пользователь может иметь разные `s_ObjectID` на разных серверах;
- один справочник может иметь разные `ParameterGroups.PK` на разных серверах;
- поэтому runtime-ключ всегда состоит из `sourceCode + groupId + objectId`;
- `GroupGuid` сохраняется и показывается как дополнительный идентификатор, но не заменяет привязку к source;
- одинаковые справочники объединяются в меню по техническому `TableName`, а внутри содержат отдельные source-binding с собственными ID и UUID.

## Страница

```text
/reporter/spravochniki
/reporter/references
```

Возможности:

- динамический список справочников, включенных флагом «Показывать в меню»;
- переключение между серверами без повторного входа;
- безопасное чтение колонок из `sys.columns/sys.types`;
- автоматический выбор обозначения и наименования;
- поиск;
- постраничный вывод;
- раскрытие иерархии по `s_ParentID`;
- карточка выбранного объекта;
- ссылка на объект в штатном T-FLEX;
- проверка политик репортера и source-scoped T-FLEX read access.

## API

```text
GET /api/reporter/references/catalog
GET /api/reporter/references/sources/{sourceCode}/groups/{groupId}/schema
GET /api/reporter/references/sources/{sourceCode}/groups/{groupId}/items
GET /api/reporter/references/sources/{sourceCode}/groups/{groupId}/items/{objectId}
```

Параметры списка:

```text
query
parentId
page
pageSize
```

## Начальная настройка

После обновления желательно один раз выполнить из страницы управления:

1. «Синхронизировать метаданные»;
2. «Создать начальные настройки».

Обновленная начальная настройка делает видимыми четыре стартовых справочника:

```text
Kartochka_proekta
Nomenclature
Documents
Files
```

Их видимость затем полностью регулируется в `/reporter/admin`.

## Ограничения этапа

- точное дерево разделов штатного `ReferenceCatalog` пока не восстанавливается;
- дерево строится внутри конкретной объектной таблицы по `s_ParentID`;
- сложные параметры из дополнительных таблиц и универсальная обработка relations будут добавлены следующим подэтапом;
- в строгом режиме права проверяются построчно, поэтому страница после фильтрации может содержать меньше запрошенного числа строк.
